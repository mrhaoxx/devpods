# DevPod 控制台式 Web UI 重新设计

日期：2026-11-09　状态：设计已逐节确认，待审阅

相关：
- `2026-11-09-devpod-audit-telemetry-design.md`：审计（一期，已上线）和实时指标（二期，未实现）。本 spec 规定的实时与汇总接口（§6）由二期实现，需要回补到那份 spec。
- 预约后端：单独写 spec（见 §2）。本 spec 只覆盖预约的界面，以及已经定下的产品规则（§5.7）。
- Mockup（已确认）：`2026-11-09-console-ui-mockups/` 下的 `direction.html`（选 A）、`ia-overview.html`、`detail.html`、`admin-users-nodes.html`、`reservation.html`。这些文件是可视化助手的 HTML 片段，用浏览器打开即可，样式以深色为例。

## 1. 目标与非目标

### 1.1 为什么重做

用户的原话："目前框架感觉信息密度比较低，而且 admin ui 很蠢"。现状：
- 外框是居中的窄栏（`max-w-3xl`，表格页 `max-w-7xl`）；导航全藏在右上角的用户下拉菜单里；页面之间靠 BackLink 跳回。
- 管理端：用户页是一串卡片，配额、策略在卡片里展开逐个编辑；"所有 DevPod"只是普通列表加了一列 Owner；CPU 拓扑是单独一页。
- 页面上没有任何实时资源数据。二期遥测还没实现。

### 1.2 目标

- 控制台式布局（mockup A）：常驻侧栏，全宽、高密度表格，KPI 条，⌘K 全局搜索。
- 深浅两套配色，默认跟随系统，可以手动切换。
- 每秒刷新的实时指标出现在所有相关位置：列表的指标列、详情页的卡片和图表、总览、节点、用户用量。
- 管理端按"一张表看全 + 批量操作 + 侧边抽屉"重做：总览、全部 DevPod、节点、用户与配额。
- 加入预约功能的全部界面：预约时间轴（拖选、取消），以及预约在详情页、新建表单、节点页、用户页、总览上的体现。
- 审计页面统一换成控制台风格。

### 1.3 非目标

- 不实现二期遥测的采集、上报和存储，那属于二期 spec；不实现预约的后端逻辑，那属于预约 spec。本 spec 只规定 UI 需要它们提供哪些接口（§6）。
- 不改认证方式（GitLab OAuth、内置密码），不改 DevPod、User 的 CRD 语义。
- 不做移动端专用布局，只保证窄屏可用（§8）。
- 不做多语言切换，界面文案统一用中文；命令、标识符、单位保持原样。

## 2. 分期与交付顺序

这次重做拆成三个子项目，每个都单独走 spec → 实施计划 → 实现：

| 顺序 | 子项目 | spec |
|---|---|---|
| 1 | 二期实时指标后端（supervisor 采集、`/ingest`、ClickHouse、SSE，加上本 spec §6 要求的节点和用户汇总） | 更新 `2026-11-09-devpod-audit-telemetry-design.md` |
| 2 | 预约后端（CRD、节点可预约标记、准入、清场和到期休眠、通知、配额） | 新写 |
| 3 | UI 重做（本 spec） | 本文件 |

UI 可以在 §6 的接口定稿后，基于 mock 数据和前两个子项目并行开发；正式切换要等 1、2 上线。

## 3. 视觉与交互基调

- **布局**：左侧常驻侧栏（宽约 180px；窄于 1100px 时收成图标栏），右侧是全宽内容区。内容区顶部是页面标题、⌘K 搜索框和页面级筛选。
- **配色**：所有颜色都定义成 CSS 变量，深浅两套。默认读取 `prefers-color-scheme`；用户手动切换后存到 localStorage，读写都要 try/catch，读不到就跟随系统。状态色语义固定：运行 = 绿，启动中 / 注意 = 黄，失败 / 告警 = 红，休眠 = 灰，选中 / 链接 = 蓝。
- **字体**：数字、名称、命令、路径用等宽字体；说明文字用系统字体。
- **密度**：表格行高约 28px；单元格里直接放指标，比如 60 秒小曲线加"7.4/8"，或者内存条加"26/32G"。用 KPI 条代替大标题卡片。
- **抽屉优先**：在列表里查看或编辑一个对象（用户、节点、新建 DevPod）时，从右侧滑出抽屉，不跳页。只有 DevPod 详情和会话详情是独立页面，因为它们内容最多，也需要能分享链接。
- **可分享的视图**：筛选、排序、当前标签页、时间范围都放在 URL 的 query 里。

## 4. 信息架构

### 4.1 侧栏

普通用户：

```
我的 DevPod   (n)
预约          (进行中/即将开始的数)
我的会话                ← 仅开启审计时显示
── 设置
SSH 密钥 · 密码
[+ 新建 DevPod]
左下：用户名 · 配额 已用/上限 · 本周预约剩余
```

管理员在上面这些之外，多出两组：

```
── 集群
总览
全部 DevPod   (运行中/总数)
节点          (n)
用户与配额    (n)
── 审计
会话 / 回放
命令 · 文件
告警          (未处理数，红色)
访问记录 · 策略
```

### 4.2 路由

| 路径 | 页面 | 可见范围 |
|---|---|---|
| `/` | 我的 DevPod | 全部用户 |
| `/devpods/:name` | DevPod 详情（`?tab=`） | 自己的；管理员可看全部 |
| `/reservations` | 预约 | 全部用户 |
| `/sessions`、`/sessions/:id` | 我的会话 / 会话详情 | 审计开启时 |
| `/settings` | SSH 密钥、密码 | 全部用户 |
| `/admin` | 集群总览 | 管理员 |
| `/admin/devpods` | 全部 DevPod | 管理员 |
| `/admin/nodes`（`?node=` 打开抽屉） | 节点 | 管理员 |
| `/admin/users`（`?user=` 打开抽屉） | 用户与配额 | 管理员 |
| `/audit/sessions`、`/audit/commands`、`/audit/files`、`/audit/alerts`、`/audit/access-log`、`/audit/policy` | 审计 | 管理员（命令、文件检索也对普通用户开放，只能查自己的） |
| `/login` | 登录 | — |

旧路径做重定向：`/settings/pubkeys` 和 `/settings/password` → `/settings`；`/admin/topology` → `/admin/nodes`；`/audit/sessions/:id` → `/sessions/:id`（管理员也用这个路径）。

## 5. 页面

### 5.1 DevPod 表格（共用组件）

"我的 DevPod"和"全部 DevPod"用同一个组件，管理员视图多一列 Owner 和批量操作。

- **列**（按优先级从高到低，窄屏从低往高隐藏）：
  - 状态和名称；
  - CPU（60 秒小曲线 + 用量/限额）；
  - 内存（条 + 用量/上限）；
  - GPU（每卡一格 + 平均利用率）；
  - 会话（数量 + 用户名）；
  - 运行时长；
  - 网络 ↓/↑（hostNetwork 的 DevPod 标 `TCP only`）；
  - RDMA ↓/↑（标 `VF` / `shared`）；
  - 节点；
  - 镜像；
  - 操作（⋯ 菜单）。
- **非运行状态的行**：Pending、Stopped、Failed 时，指标列合并成一格文字说明：拉取镜像进度、休眠多久和 PVC、失败原因和重试倒计时。
- **预约标记**：跑在可预约节点上的 DevPod，在名称旁加标签"预约中 · 剩余 2h"，或者"14:30 将被清场"。
- **顶部**：
  - 过滤框，支持 `user:`、`node:`、`phase:`、`gpu>0` 这样的语法；
  - 状态 chip（Running / Pending / Stopped / Failed，带计数）；
  - 管理员额外有："空转 >24h""GPU only"。
- **管理员批量操作**：多选后可以休眠、启动、删除，删除需要输入确认。
- **数据来源**：DevPod 对象来自现有 watch 流；指标来自 `live/devpods`，每个单元格只订阅自己那一行的数据。

### 5.2 DevPod 详情（`/devpods/:name`）

页头：
- 名称、状态和运行时长；
- 操作：复制 SSH、编辑（打开抽屉）、休眠/启动、删除；
- 元信息一行：节点、镜像、IP、home 存储、协作者、Kore 绑定；管理员额外看到 Owner；
- 有预约时显示横幅：剩余时间、到期动作、"延长"和"提前释放"按钮，见 §5.7；节点即将被清场时显示黄色警告横幅。

六张实时卡片：CPU、内存、GPU、网络、RDMA、磁盘 IO。每张都是"数值 + 60 秒小曲线"，没有遥测数据时显示"—"。

标签页：
- **概览**：
  - SSH 命令和 ssh config 片段，都可以一键复制；
  - 在线会话（带回放链接，只显示有权限看的）；
  - 占用最高的 10 个进程（PID、命令、会话归属及归属依据 exact/tmux/SSH_CONNECTION、CPU、RSS、GPU 显存）。
- **监控**：
  - 时间范围：实时 1s / 15m / 1h / 24h / 7d；
  - 六张图：
    - CPU：使用、限额线、throttled；
    - 内存：anon 和 file 叠加、限额线；
    - GPU：按卡显示，可切换利用率、显存、功耗、温度；
    - 网络：可拆分 TCP 和其他；
    - RDMA：按设备，带精度标签，可切换 CNP 和重传；
    - 磁盘 IO。
  - 超过 1 秒粒度的保留期后，自动改用分钟粒度的数据。
- **进程**：全部进程的表格，每秒刷新，可以排序。别人会话里的进程，命令行脱敏（审计 spec §9.2）。
- **会话**：这个 DevPod 上的会话（按权限过滤），带回放入口和拦截标记。
- **容器**：OS 和内核、限额和 cpuset、GPU、RDMA 设备、监听端口、存储。
- **事件**：现有的事件流。

### 5.3 集群总览（`/admin`）

每秒刷新。
- **KPI 条**：
  - CPU、内存、GPU：使用 / 可分配；
  - DevPod：运行、启动中、失败的数量；
  - 在线会话和用户数；
  - RDMA 合计。
- **节点热力条**：每台节点一格。底色表示 CPU 使用率，角标是"GPU 已占/总数"；NotReady 的节点显示为灰色，可预约的节点加一个小标记。点击跳到节点抽屉。
- **"需要处理"列表**：服务端算好、按影响排序。每条都带一个直接操作。
  - 占着 GPU 空转超过阈值：休眠。"空转"定义为 24 小时内没有会话，并且 CPU 平均低于 5%、GPU 利用率平均低于 5%，阈值可配置；§5.1 的"空转 >24h"筛选用同一个定义；
  - 启动超过 10 分钟仍是 Pending：事件；
  - 审计告警：回放；
  - 配额用到 90% 以上：调整；
  - 30 分钟内要开始的预约清场名单：查看；
  - 已经到期但 DevPod 还在跑：休眠。
- **用量最大的用户**：DevPod 数、CPU、内存、GPU。
- **最近审计活动**：实时滚动。

### 5.4 节点（`/admin/nodes`）

- **表格**，每台节点一行：
  - 名称、状态；
  - CPU 已分配/可分配（条），DevPod 实际 CPU（小曲线）；
  - 内存已分配；
  - GPU（每卡一格，标型号）；
  - RDMA 设备；
  - DevPod 数；
  - 标签；
  - "可预约"开关；
  - 当前和下一个预约。
- **筛选**：可调度、有 GPU、NotReady、可预约，以及按标签过滤。
- **点行打开抽屉**：
  - 这台节点上的 DevPod，可以多选后休眠；
  - 每张 GPU 卡的占用者；
  - Kore 的 CPU 拓扑（替代现在的 `/admin/topology`）；
  - 这台节点的预约日历，可以取消任意预约。

### 5.5 用户与配额（`/admin/users`）

- **表格**，每个用户一行：勾选框、用户名（管理员加徽标）、来源（LDAP、密码、OIDC）、DevPod 用量/配额、CPU/内存/GPU 用量对配额的条（到 80% 变黄，超出变红）、每周预约时长、最近会话、是否有自定义审计策略。自定义的配额用 `*` 标出，表格底部写明全局默认值。
- **快捷筛选**：有运行中、配额 >80%、自定义配额、自定义审计策略、管理员、从未登录。
- **批量操作**：勾选后可以设配额、设审计策略、重置密码（给每个人生成随机密码，一次性展示，可下载 CSV）、休眠其全部 DevPod。
- **导入 CSV**：列为 `username,displayName[,password]`；不填密码就随机生成。先预览，确认后提交，结果逐行显示成功或失败。
- **点行打开抽屉**：
  - 配额编辑，每个字段旁边显示当前用量，留空表示用默认值；
  - 这个用户的 DevPod，带"打开"链接；
  - 最近会话，带回放；
  - 审计策略覆盖（复用 `AuditPolicyEditor`）；
  - SSH 公钥数量和来源；
  - 设为管理员、删除用户，都需要确认。

### 5.6 新建 / 编辑 DevPod（抽屉）

- **字段**：模板、名称、镜像、资源（CPU/内存/GPU）、节点、持久化、协作者。
- **配额**：输入时实时检查，超出时就在对应字段旁边提示。
- **节点选择**：
  - 默认"自动"；
  - 下拉列表里每台节点都显示剩余资源和预约状态：可用、你的预约中（剩余）、空闲但 HH:MM 起被他人预约、被他人预约中（不可选）；
  - 选的是可预约节点、而你又没有有效预约时，提示"该节点 HH:MM 将被清场"。
- **编辑会重建 Pod 时**：沿用现有的提示（会断开会话）。

### 5.7 预约（`/reservations`）

产品规则已经定下来（后端语义以预约 spec 为准）：
- **预约单位**：整台节点独占。只有管理员标记为"可预约"的节点才能被预约。
- **生效**：先到先得，时间段不冲突就立即成功。用配额防止滥用，默认每人每周 24 小时，管理员可以按用户调整。
- **时间规则**：30 分钟一档，单次最长 24 小时，最多提前 14 天。这几个值是集群级配置。
- **空闲时段**：没有预约的时候，任何人都可以用这台节点。预约开始前 30 分钟通知节点上的其他用户，开始时把他们的 DevPod 自动休眠（数据保留）。
- **使用方式**：手动启动。预约只给资格，用户在预约时段内创建或启动 DevPod 时自己选这台节点；预约人的协作者也能用。
- **到期或提前释放**：预约到期，或者持有人提前释放时，所有用到这台节点的 DevPod 都会被休眠。到期前 30 分钟和 5 分钟提醒。
- **延长**：后面的时段没有被别人预约时可以延长，计入配额。
- **管理员**：可以取消任何人的预约，被取消的用户会收到通知。

页面：
- **时间轴**：
  - 每行一台可预约节点，左边写型号和规格；横轴是时间（3 / 7 / 14 天）；红线标出当前时刻；
  - 自己的预约用蓝色，别人的用灰色并写上用户名（谁约了是公开的），空闲时段用虚线框；
  - **拖动选择**：在空闲区域按住拖动，按 30 分钟对齐，拖的过程中显示时长和本周剩余额度；拖到冲突区域时选区变红，不能提交；松手后弹出确认框，写明节点、时段、额度扣减，以及会被清场的他人 DevPod 数量；
  - **点自己的预约块**：弹出菜单，有修改（拖动两端）、延长、取消；
  - 管理员点任何预约块都能取消。
- **我的预约**：列出即将开始、进行中、已结束的预约，可以修改、取消或提前释放。
- **新建预约表单**：节点、开始、结束，和拖选是同一套校验；结果和拖选一样。

在其他页面上的体现：详情页横幅（§5.2）、表格标签（§5.1）、新建表单的节点状态（§5.6）、节点页的开关和日历（§5.4）、用户页的每周预约配额（§5.5）、总览的"需要处理"（§5.3），以及通知（§5.10）。

### 5.8 审计

- **会话列表**：控制台式表格，列有用户、DevPod、来源 IP 和认证路径、开始时间、时长、通道类型、文件传输数、拦截、告警、gap。管理员可以按用户、DevPod、时间筛选；普通用户只看到自己的会话。
- **会话详情**：
  - 左边是时间线：通道、命令、文件、拦截、告警按时间穿插排列；右边是回放播放器；点时间线上的条目跳到对应时刻；
  - 只有 pty 和 shell 通道提供回放。sftp、scp 这类二进制通道显示文件事件和原始流下载（仅管理员），不提供回放。这同时修掉审计一期审查里遗留的 Minor #19；
  - 下载文件前提示"此操作将被记录"。
- **命令、文件检索**：全宽表格，支持子串、路径和 sha256 搜索，时间范围写在 URL 里。
- **告警、访问记录**（仅管理员）：表格加筛选。
- **策略**（`/audit/policy`）：只读显示集群默认策略，列出设置了自定义策略的用户（链接到用户抽屉）；还要显示 VS Code 绕过提示（`WarnVSCodeBypass`）。

### 5.9 ⌘K 全局搜索

- 按 ⌘K 或 Ctrl+K 打开，也可以点顶部的搜索框。
- 结果分四组：用户、DevPod、会话、命令，每组前 5 条；普通用户只能搜到自己的内容。回车跳转。
- 在 DevPod 结果上有快捷动作：复制 SSH 命令、休眠/启动、打开监控。

### 5.10 通知

- 顶部有一个铃铛：显示未读数，展开是通知列表。新通知来时在右下角弹出 toast。
- 通知类型：清场预告、预约到期提醒、预约被管理员取消、DevPod 启动失败。
- 数据来自 `GET /api/me/notices` 和 SSE 的 `notice` 事件。

### 5.11 设置与登录

- **设置**：一个页面分两块，SSH 密钥（`pubkeySelfService` 关闭时只读）和密码。
- **登录页**：根据 `features` 显示密码登录、GitLab 登录或两者都有，跟随深浅色。

## 6. 数据接口约定

UI 只调用下面这些接口。前两个子项目按这里实现；字段的细节在实施计划里定成 TypeScript 和 Go 两边对应的类型。

### 6.1 实时流（SSE）

| 接口 | 频率 | 内容 |
|---|---|---|
| `GET /api/live/devpods?scope=mine\|all` | 1s | 只含运行中的 DevPod。每个 DevPod 一条紧凑记录：`cpu, cpuLimit, mem, memLimit, gpu[{util, memUsed, memTotal}], netRx, netTx, netKind(tcp-only?), rdmaRx, rdmaTx, rdmaKind(vf/shared), ioR, ioW, sessions[{user}]`。`scope=all` 仅限管理员 |
| `GET /api/devpods/{name}/stream` | 1s | 现有的流，新增两种事件：`metrics`（完整样本，GPU 按卡、RDMA 按设备分开）和 `processes`（默认推前 10 个；切到进程标签页时，客户端带 `?procs=all` 重连） |
| `GET /api/admin/live/overview` | 1s | KPI 合计、各节点汇总（CPU 使用、GPU 已占/总数、是否可预约、状态）、用量最大的用户、"需要处理"列表 |
| 上面所有流的 `notice` 事件 | 事件触发 | 当前用户的通知 |

所有流都沿用现有 `sse()` 的退避重连。服务端每次推送的是这一秒的完整快照，不是增量，所以断线重连后不需要补数据。

### 6.2 普通接口

| 接口 | 用途 |
|---|---|
| `GET /api/devpods/{name}/metrics?range=&step=` | 历史曲线（审计 spec §9.3） |
| `GET /api/admin/nodes`、`GET /api/admin/nodes/{n}` | 节点信息：可分配和已分配资源、DevPod 实际用量汇总、GPU 每卡占用者、是否可预约、当前和下一个预约、Kore 拓扑 |
| `PUT /api/admin/nodes/{n}/reservable` | 开关可预约 |
| `GET /api/admin/users` | 用户列表，带当前用量、配额、每周预约配额、策略标记、最近会话、公钥数量 |
| `POST /api/admin/users:batch` | 批量操作 `{names[], op: setQuota\|setPolicy\|resetPassword\|hibernateAll, args}`，返回每个用户的执行结果 |
| `POST /api/admin/users:import` | CSV 导入：`?dryRun=1` 只预览；返回每行的执行结果，以及生成的密码（仅在这一次响应中返回） |
| `GET /api/search?q=` | ⌘K 搜索，四类各前 5 条，按权限过滤 |
| `GET /api/reservations?from=&to=[&node=]` | 时间轴数据（所有人可见，含预约人的用户名） |
| `POST /api/reservations` | 新建预约 `{node, start, end}`；冲突返回 409，超出配额返回 403，两种错误都带原因 |
| `PATCH /api/reservations/{id}` | 修改或延长 |
| `DELETE /api/reservations/{id}` | 取消；已经开始的就是提前释放 |
| `GET /api/me/reservation-quota` | 本周额度：已用、上限、规则（时间粒度、单次上限、提前天数） |
| `GET /api/me/notices`、`POST /api/me/notices/{id}/read` | 通知 |

### 6.3 降级

- 没有遥测数据（旧 Pod）：指标单元格显示"—"，悬停提示"监控在 Pod 下次重建后生效"。
- ClickHouse 不可用：DevPod 列表、节点、用户照常显示，数据来自 k8s 和缓存；历史曲线、审计页和"最近活动"显示错误状态，其他部分照常。
- SSE 断开：页面顶部显示一条细条"实时数据重连中…"，表格保留最后一次的值，并且变暗。

## 7. 前端架构

### 7.1 技术栈

保留 React 18、react-router 6、TanStack Query 5、Tailwind 4、Vite 和 vitest。新增依赖：

| 依赖 | 用途 | 许可 |
|---|---|---|
| `uplot` | 时序图（1 秒刷新） | MIT |
| `@tanstack/react-table` | 无样式表格：排序、列显隐、多选 | MIT |
| `@radix-ui/react-dialog`、`-popover`、`-dropdown-menu`、`-tooltip` | 抽屉、弹层、菜单、提示，自带键盘操作和无障碍支持 | MIT |
| `cmdk` | ⌘K 搜索框 | MIT |
| `@testing-library/react`、`jsdom`（dev） | 组件测试 | MIT |
| `@playwright/test`（dev） | 端到端 | Apache-2.0 |

### 7.2 目录

```
web/src/
  app/        Shell（侧栏、顶栏）、路由、主题、通知铃铛、旧路由重定向
  design/     颜色 tokens（index.css 中的 CSS 变量，深浅两套）和基础组件：
              Button Chip Badge Panel Kpi Meter Sparkline StatusDot Drawer
              EmptyState DataTable（基于 react-table）TimeSeriesChart（基于 uPlot）
  data/       api.ts（有类型的客户端）、各资源的 query hooks
    live/     LiveHub：SSE 连接按流复用（引用计数），每个 key 保存 60 秒环形缓冲；
              单元格用 useSyncExternalStore 只订阅自己那一行，每秒刷新不会重渲整张表
  features/   overview devpods reservations nodes users audit settings search notices
  lib/        保留并移入：format columns tabs audit policy（连同现有测试）
```

旧的 `pages/`、`ui.tsx`、`components/` 整体删除，有用的逻辑移到上面的目录里。

### 7.3 状态与刷新

- 服务端数据统一由 TanStack Query 管理。实时数据不进 Query 缓存，只进 LiveHub。
- 筛选、排序、标签页、时间范围、打开的抽屉都放在 URL query 里，有一个工具函数负责双向转换。
- 批量操作和其他修改成功后，让相关 query 失效重取；不做乐观更新，只有预约拖选在提交前显示占位块。

## 8. 窄屏与可访问性

- 窄于 1100px：侧栏收成图标栏，鼠标悬停时展开。
- 窄于 700px：侧栏变成抽屉式菜单；表格按列优先级隐藏到只剩"状态、名称、主要指标"；所有抽屉全屏显示。
- 页面不出现横向滚动；表格自己的横向滚动只在用户主动展开全部列时出现。
- 所有交互都能用键盘完成。颜色从不单独表达状态，总会配上文字或形状，比如状态点旁边写状态名。
